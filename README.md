# Бот автовыплат работникам (TON)

Telegram-бот на **aiogram 3.x**: работник задаёт TON-кошелёк, админ начисляет ему
баланс, работник по кнопке **«Вывести»** получает **моментальную выплату в TON**
с горячего кошелька. Хэш транзакции возвращается в чат.

## Как работает

1. Работник жмёт `/start` → регистрируется.
2. **💼 Кошелёк** — задаёт свой TON-адрес (`UQ.../EQ...`).
3. Админ: `/credit <user_id> <сумма_TON> [коммент]` — начисляет баланс.
4. Выплата — в одном из двух режимов:

**Авто (`AUTO_PAYOUT=true`).** TON уходят сразу при начислении, работнику
не нужно ничего нажимать. Если кошелёк не задан или баланс ниже минимума,
деньги копятся на балансе до следующего начисления.

**По кнопке (`AUTO_PAYOUT=false`, по умолчанию).** Работник жмёт
**💸 Вывести** → подтверждение → бот моментально шлёт весь баланс.

Оба режима идут через один и тот же код (`bot/payout.py`), поэтому
гарантии одинаковые и не разъезжаются при правках.

## Топ воркеров

**🏆 Топ-10** — рейтинг по сумме реально выплаченного, с медалями за первые
три места и числом выплат. Считается по фактически проведённым выплатам,
незакрытые и проваленные заявки в него не попадают.

Баланс резервируется в одной транзакции БД (списание + заявка `processing`),
поэтому **двойной вывод невозможен** даже при спаме кнопки или рестарте.
При сетевом сбое отправки средства **возвращаются** на баланс, админу уходит алерт.

## Команды

| Команда | Кто | Что |
|---|---|---|
| `/start` | работник | регистрация, меню |
| `/id` | любой | узнать свой Telegram id |
| `/credit <id> <TON> [коммент]` | админ | начислить баланс |
| `/stats` | админ | сводка: работники, балансы, выплаты |

## Демо-режим (без кошелька, без реальных денег)

`DRY_RUN=true` — бот поднимается целиком, все меню и кнопки живые, но вместо
отправки TON возвращается фейковый хэш и в лог пишется предупреждение.
Seed-фраза при этом не нужна. Годится, чтобы прокликать весь флоу перед боевым запуском.

```bash
pip install -r requirements.txt
export BOT_TOKEN=<токен от @BotFather>
export ADMIN_IDS=<твой telegram id>
export DRY_RUN=true
python -m bot.main
```

Отдельно есть `demo.py` — прогон полного цикла вообще без Telegram:

```bash
python demo.py
```

## Запуск локально

```bash
pip install -r requirements.txt
cp .env.example .env      # заполнить BOT_TOKEN, ADMIN_IDS, WALLET_MNEMONIC
python -m bot.main
```

Узнать свой `ADMIN_IDS`: запусти бота, напиши ему `/id`.

## Деплой на Railway

1. Push в GitHub.
2. Railway → New Project → Deploy from GitHub Repo → выбрать репозиторий и ветку.
3. **Volume (обязательно).** Settings → Volumes → Add Volume, mount path `/data`.
   Затем в Variables поставить `DB_PATH=/data/payouts.db`.
   Без этого файловая система эфемерная: база стирается при каждом редеплое,
   балансы и история выплат обнуляются.
4. Variables → добавить остальное из `.env.example`
   (`BOT_TOKEN`, `ADMIN_IDS`, `WALLET_MNEMONIC`, `WALLET_VERSION`, ...).
5. Deploy. Процесс стартует по `railway.json` / `Procfile`.
6. В логах при старте печатается адрес горячего кошелька — сверь, что это твой.

Порядок первого запуска: `TON_TESTNET=true` → проверить вывод на тестовой сети →
переключить на mainnet и пополнить горячий кошелёк.

## Env

Все переменные — в `.env.example`. Ключевое:

- `WALLET_MNEMONIC` — seed-фраза (24 слова) **горячего** кошелька, с которого уходят выплаты.
  Держи на нём только оперативный остаток. Никогда не коммить реальную фразу — только через Variables.
- `WALLET_VERSION` — версия контракта кошелька: `v3r2` | `v4r2` | `v5r1` (обычно `v4r2`).
  Должна совпадать с реальной версией, иначе баланс «не найдётся».
- `TON_TESTNET=true` — сначала проверь на testnet, потом переводи на mainnet.
- `MIN_WITHDRAW_TON` — минимум для вывода.

## Безопасность

- Сумма выплаты списывается с баланса **до** отправки (резерв), возврат при ошибке.
- Комиссия сети платится с горячего кошелька сверх суммы — держи там запас на газ.
- Адрес получателя валидируется, финальную проверку делает сеть при отправке.
- Все секреты — только через env, не в коде.

## Оформление

Весь интерфейс собран на **премиум-эмодзи** — обычных эмодзи в боте нет ни в
сообщениях, ни на кнопках. Иконки взяты из паков Playerok Icons, Finance и
Animated (исходный дамп — `emoji_index.json`, 3125 записей).

- в тексте — тегом `<tg-emoji>`
- на кнопках — полем `icon_custom_emoji_id`, поэтому подпись остаётся чистым
  текстом и обычный эмодзи не подставляется даже при сбое

Правило «ни одного обычного эмодзи» проверяется тестом: он сканирует
`keyboards.py` и оба файла хендлеров и падает, указывая файл и строку.

**Все кнопки цветные.** Цвет назначается по смыслу действия:

| Цвет | Где |
|---|---|
| зелёная `success` | вывод средств, подтверждение, сохранение кошелька |
| красная `danger` | отмена, панель администратора |
| синяя `primary` | разделы, навигация, статистика |

### Требование Telegram Premium

Кастомные эмодзи отображаются, **только если у аккаунта бота есть Telegram
Premium**. Без него Telegram отклоняет сообщение целиком, поэтому в сессии
стоит аварийный откат: при первом отказе бот один раз пишет в лог, переходит
на запасные символы и повторяет запрос — бот не ломается. Факт отключения
виден в `/stats`, чтобы это не осталось незамеченным.

Отключить попытку совсем: `USE_PREMIUM_EMOJI=false`.

### Фото-шапка меню

`MENU_PHOTO` — file_id или прямая ссылка на картинку. Если задано, меню
приходит фото с подписью, и навигация по разделам редактирует подпись.
Если ссылка битая, бот молча покажет меню текстом.
